
# 개발자 비상 근무
## 실행 흐름

1. 프로그램이 "비상 근무를 배정할 월과 시작 요일을 입력하세요>"를 출력한다.
2. 사용자에게 월과 시작 요일을 입력받는다.
   1. 올바르지 않은 입력을 할 경우 "[ERROR]"로 시작하는 에러 메시지 후 다시 입력받는다.
3. 프로그램이 "평일 비상 근무 순번대로 사원 닉네임을 입력하세요>"를 출력한다.
4. 사용자에게 평일 비상 근무 순번을 입력받는다.
   1. 올바르지 않은 입력을 할 경우 "[ERROR]"로 시작하는 에러 메시지 후 다시 입력받는다.
5. 프로그램이 "휴일 비상 근무 순번대로 사원 닉네임을 입력하세요>"를 출력한다.
6. 사용자에게 휴일 비상 근무 순번을 입력받는다.
    1. 올바르지 않은 입력을 할 경우 "[ERROR]"로 시작하는 에러 메시지 후 다시 입력받는다.
7. 프로그램이 비상 근무표를 출력한다.

## 기능 목록
### 스케줄러 컨트롤
- [ ] 전체 스케줄을 관리하는 스케줄러는 평일/휴일 근무와 월 정보, 직전 근무자를 상태로 관리한다.

### 비상 근무 월과 시작 요일 입력
- [x] 월은 `enum` 타입으로 취급하며 휴일 리스트와 최대 날짜를 가진다.
- [x] 요일은 숫자 인덱스로 관리하며, 요일 enum을 통해 순환 및 출력 책임을 분리한다.

### 근무자 명단 관리
- [ ] 근무자 명단은 배열 형태로 관리한다.
- [ ] 근무자 명단 객체는 index를 가진다.
- [ ] 근무자 명단에서 연속 근무가 나올 시 swap을 통해 진행한다.

### 예외처리 
- [x] 월과 시작 요일
  - [x] 월은 숫자인지와 1~12월인지 검사한다.
  - [x] 요일은 [월,화,수,목,금,토,일]인지 검사한다. 
- [ ] 비상 근무
  - [ ] 비상 근무 이름은 1자 이상 5자 이하인지 검사한다.
  - [x] 비상 근무 리스트는 최소 5명 최대 35명이다. 
  - [x] 비상 근무는 중복이 있으면 안된다.

## 💻 프로그래밍 요구 사항

- JDK 17 버전에서 실행 가능해야 한다.
- `Application.main()`에서 프로그램을 시작한다.
- `build.gradle` 파일은 변경하지 않는다.
- `camp.nextstep.edu.missionutils` 라이브러리 외 외부 라이브러리를 사용하지 않는다.
- `System.exit()`를 호출하지 않는다.
- 제공된 파일 및 패키지 구조를 변경하지 않는다.
- Google Java Style Guide를 준수하여 코드를 작성한다.
- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
- 3항 연산자를 쓰지 않는다
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
- 함수(또는 메서드)의 길이가 15라인을 넘어가지 않도록 구현한다.
- else 예약어를 쓰지 않는다.
- Java Enum을 적용하여 프로그램을 구현한다.
- 구현한 기능에 대한 단위 테스트를 작성한다. 단, UI(System.out, System.in, Scanner) 로직은 제외한다.

## ✍️ 커밋 메시지 규칙

- AngularJS Git Commit Message Conventions를 따른다.

- **커밋 메시지 구조**

  ```
  type: subject

  body (optional)

  footer (optional)
  ```

- **Type 종류**

    - `feat`: 새로운 기능 추가
    - `fix`: 버그 수정
    - `docs`: 문서 수정
    - `style`: 코드 포맷팅, 세미콜론 누락 등 (코드 변경이 없는 경우)
    - `refactor`: 코드 리팩토링
    - `test`: 테스트 코드 추가/수정
    - `chore`: 빌드 업무 수정, 패키지 매니저 수정 등

- **예시**

  ```
  feat: 쉼표 구분자로 숫자 덧셈 기능 구현
  ```
